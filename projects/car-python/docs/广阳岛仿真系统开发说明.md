# 辰龙广阳岛仿真系统开发说明

## 当前定位

本仓库以原有 Three.js + Pyodide 教学仿真器为底座，已经形成可运行的广阳岛三任务原型。当前目标是冻结比赛核心数据模型和前端闭环，不把客户端成绩当作官方权威结果。

当前原型采用 100 分展示与重算口径：任务完成 40 分、路径与规则 25 分、自主控制 15 分、完成效率 20 分。最终评分项、权重和可记录指标仍以正式任务规则及系统实际发布为准，因此持续违规费率、单次扣分和效率曲线仍是可替换参数，不能视为官方判分口径。历史 60 分记录保留原始冻结定义，只在公共记录列表和混合榜单中等比例归一为 100 分。

## 已实现

- 三个“广阳岛综合任务”任务共享道路底图，按目标物、混淆物、障碍物与有序途径点数量逐级增加难度；任务1 的目标物入库、混淆物移出道路、障碍绕行、4 个巡检点与最终返航共形成 8 个任务单元。
- 直接使用仓库内的《广阳岛仿真沙盘地图.png》作为裁切后的地面纹理，并以同一张原图的像素坐标标定道路、景点、停车位和任务点。
- `TaskEngine`：任务定义和进度判定已进入不依赖 DOM/Three.js 的纯核心层。`chenlong.task/v5` 的 `composite` 模式支持目标物入库、混淆物在抓取后完整移出任意道路边界、有序检查点、指定障碍零碰撞和最终返航门控；道路外判定按物体圆盘到所有道路边缘的冻结净距重算，不再依赖固定移除点，而释放姿态仍允许小车留在道路内。碰撞指定障碍后最多只能完成 7/8，必须重置重试；投错区域、提前返航、跳序、驻留和完成后重复采样也不会伪造进度。旧 task/v1～v4 记录继续兼容。
- `RuleEngine`：当前三个任务保留道路与限速数据供传感器和局部道路控制使用，但显式关闭超速、逆行、红灯和禁行区违规事件及扣分；当前只记录驶出道路和碰撞。通用引擎继续保留这些旧规则的实现，仅用于带冻结旧配置的历史记录兼容复算。
- `CompetitionJudge`：当前广阳岛按 40/25/15/20 生成实时分项和 100 分总分，拒绝零任务、越界任务数等非法状态；旧记录仍按自身冻结的 25/15/10/10 定义复算。
- `DeterministicSimulator`：车辆运动统一使用 20ms 固定步长，版本化车辆速度、转向、半径、碰撞皮肤和矩形地图边界；浏览器 `sleep()` 只控制动画播放节奏，不再决定物理位移。随机种子已经接入独立 PRNG，装饰渲染不会消耗比赛随机流。
- `PackageStateEngine`：交互定义 v2 区分 `target`、`distractor` 和 `obstacle`；目标物与混淆物可抓取，障碍物不可抓取并始终参与碰撞。初始状态、顶层抓取、夹爪持有、边界限制、吸附堆叠和动态碰撞体进入纯核心层。页面只提交 `package_grab` / `package_release` 意图并呈现核心返回的结果，不能用客户端声称的对象编号、角色或落点改写重放；旧 v1 记录继续按目标物语义兼容。
- `RunRecorder`：v4 记录把基础控制、导航查询、局部道路控制、抓放、人工介入和视觉查询统一为带 `seq/tick/t` 的类型化输入；同时内嵌不可变的仿真、导航、交互、任务、规则和评分定义。任务、规则、超时与效率时间均由仿真 tick 推进，不再取决于浏览器帧率；达到时限的 tick 会先保存终止遥测，再以 `timeout` 结束，边界 tick 不接受任务完成。
- `ReplayPlayer`：v4 从类型化输入重新执行基础控制和局部道路控制，重新投影导航查询，重建车辆与包裹状态，并独立重算任务、规则、人工介入扣分与总分；记录中的 samples、events 和 result 只用于一致性校验，篡改它们不会改变重算结果。v3 保留车辆级确定性回放，v2 旧记录仍可按遥测播放并明确标记为非确定性模式。页面 HUD 已提供“回放本次运行”，并在回放中恢复包裹、持有状态和任务进度。
- 页面实时计时与评分 HUD，运行结束后可以回放或导出 `RunRecord.json`。
- 本地 Node 校验与归档后端：同源托管前端，并提供健康检查、临时校验、比赛场次和提交归档 API；JSON 解析与重放在独立 Worker 中执行，具有 40 MiB 请求上限、10 秒 Worker 超时、默认 4 个并发槽、最多 512 位且最长等待 90 秒的 FIFO、静态资源白名单和安全 MIME。整个浏览器到后端校验请求的等待上限为 120 秒。普通记录会在取得队列位置后才读取大体积草稿，避免等待请求同时把全部记录载入内存。服务端为每场签发唯一 `sessionId/runId/challengeDigest`；公开的 `challengeDigest` 是加入 256 位随机数的不可枚举场次承诺，随机数、完整赛题定义与真实定义摘要仅保存在服务端。服务端只保存提交 token 的 SHA-256，并用冻结赛题定义重放；原始记录、报告和清单原子写入 `.runtime/`。页面可区分 `verified`、`partial`、`invalid` 与服务错误。全部结果仍为 `authoritative: false`。
- 五局同源评测：一次锁定一份 Python 源码，从服务端私有目录为同一张广阳岛地图选择固定 5 个三类对象布置，并只按顺序下发当前局。每局必须先绑定唯一场次、运行、布局承诺和运行定义，服务端完成确定性重算与原子归档后才推进；`invalid`、`timeout`、主动关闭或过期产生的 `missing` 均计 0 分。公开汇总按固定五局分母计算 `70% × 均分 + 30% × 最低分`，当前任务满分 100。当前局在本地浏览器中运行并可被技术手段检查，因此仍是 `authoritative: false` 的可审计多局筛选，不是强反作弊；未来局布局不会提前下发。
- `robot.forward(厘米)` 和 `robot.backward(厘米)`，只接收一个 0.1～500 厘米的距离参数；行驶按固定速度和 20ms 步长换算，最终位移以厘米为准。
- 车载虚拟摄像头：在车体前方挂载独立的 640×480 `PerspectiveCamera` 与 `WebGLRenderTarget`，按视觉指令渲染并读取 RGBA 像素，垂直翻转后交给共享的 `vision-pixel-core.js`。固定的 `chenlong.virtual-pixel/v2` 像素检测器覆盖三类任务物体和视觉标记；正式任务的道路外移除由道路几何判定，不向学生程序返回坐标。训练通过广阳岛同图模式完成，不创建额外训练地图，也不启用正式比赛场次。虚拟模式不启用用户模板或通用 YOLO 回退；`observe()` 只返回类别、方位、估算距离、置信度和稳定状态，`holding()` 只返回夹爪持有类别。每个参与程序决策的虚拟画面以 PNG、尺寸、帧号和 SHA-256 写入稀疏证据账本，查询输入只引用此前已保存的画面。
- 导航传感器：`mission()` 返回当前冻结地图的公共道路级任务锚点（停车点、存放点、途径点、返航点的 `roadId/progressCm`）；普通单局还返回目标物、混淆物和障碍物的 `role/roadId/progressCm` 路径锚点，供学生程序按拓扑规划，到达后仍必须通过摄像头确认并抓放；练习/筛选五局的私有布局始终返回空物体列表。`task_state()` 返回确定性任务引擎已确认的进度，`release_preview()` 只给出当前夹取物立即释放能否执行、能否完成投放与混淆物道路边界余量，`odometry()` 使用本次程序的初始车体坐标系返回相对位移、相对航向和累计实际里程；`road_state()` 复用规则引擎的冻结道路几何与同一时刻碰撞世界，返回道路 ID、沿道路进度、两端节点、节点/出口、中心偏移、对齐误差、左右余量和五米内前方净空；`map_graph()` 返回无坐标的公开道路节点、边、长度与单行属性。六者都不包含地图绝对坐标、推荐出口、规划路线或预落点坐标，也不推进仿真时间。正式运行把查询记录为 `navigation_query`，回放使用同一投影器严格重算结果；该层只提供任务语义、定位、拓扑、局部净空与安全投放确认，路线搜索与出口选择仍由学生代码完成。
- 局部道路控制：`follow_road(max_cm=100, speed=40, obey_speed_limit=False)` 只沿当前道路短程居中行驶，`take_exit(road_id, speed=30, obey_speed_limit=False)` 只执行学生在当前道路节点指定的合法出口；两个控制的最后一个参数为 `True` 时，都会在每一个仿真 tick 按冻结道路和限速区自动钳制实际速度，但不会寻找节点、选择出口、自动绕障或规划路线。当前冻结契约为 `chenlong.navigation/v6` 与 `chenlong.navigation-control/v8`，所有公开距离和控制参数均按物理厘米换算；旧 v5/v7 记录继续按原契约回放。每场最多 300 次局部控制，与 1,000 次导航查询预算独立。两端节点判定范围发生重叠的短道路会驶到程序选定的实际端点，再报告 `junction`，保证随后 `road_state()` 的节点和出口与拓扑一致；这仍是局部循路，不会为学生选择下一条道路。每次有效格式请求都以单条 `navigation_control` 记录参数、停止原因、实际距离和耗时 tick，重放通过同一 `NavigationActionRunner` 重新执行车辆、碰撞、任务和规则推进并严格核对结果。`approach()` 则会根据摄像头画面实际执行小步转向和前进，其自动前进脉冲限制在 30% 以内。
- Pyodide、WASM 和标准库全部从项目本地加载，不依赖外部 CDN 或对象存储；项目仍使用了随仓库分发的第三方开源组件。
- Node 自动化测试，覆盖道路几何、导航 v3 任务语义/进度投影、v2/v1 回放兼容、无坐标拓扑、局部道路控制与独立预算、持续违规、红灯穿越时刻、评分状态校验、任务顺序/跳序/跨点/提前返航/超时边界、固定步长分块一致性、种子状态、解析碰撞、矩形边界、v4 交互与总分重算、输入/遥测/事件/结果篡改诊断、视觉 PNG 哈希与预算、仿真时钟、100ms 记录节流、虚拟摄像头与像素视觉契约、DOM/静态资源契约、本地 Pyodide 实际执行，以及后端 MIME、路径穿越、输入上限、Worker 超时和并发隔离。

## 五局同源评测与接口边界

五局评测不是把任务复制到五张地图，也不是给学生程序增加路线答案。它固定使用同一份广阳岛地图、任务、规则、评分定义和一份锁定源码，仅从经过可解性校验的服务端私有目录选择 5 个三类对象布置。私有序列在批次创建时绑定承诺，之后只能按 `1 → 5` 串行推进；公开批次状态中的布局信息只有当前局的目录版本、地图版本、序号和 `layoutCommitment`，没有任何物体坐标。申请当前局租约时才返回该局的 `runDefinition` 和交互位置，未来局不会出现在响应、页面状态或恢复缓存中。

私有目录采用显式版本注册表。`2026.08-private-layouts.1` 的原有 6 套布局、默认导出和选择算法完整保留，固定 seed 下的布局顺序与承诺已有字节级回归快照，旧批次可以继续精确重算。新增的 `2026.08-private-layouts.2` 从 18 个既有锚点的 `6 × 6 × 6 = 216` 个组合开始，逐个通过原有严格目录校验；其中 18 个组合因混淆物与障碍物的物体净间距小于 1.25 个内部单位（15.625 厘米）被排除，剩余 198 个组合以冻结清单进入目录，不在请求期间临时随机生成布局。

`tools/validate-guangyang-private-layout-solvability.js` 使用正式 task/v5、交互定义、规则、车辆仿真和公开动作范围逐套执行内部参考路线。v2 冻结基线为 198/198 套完成 `8/8`、198/198 套零碰撞、198/198 套零违规，参考完成时间 95.98–223.04 秒；参考分数为 95.7–100.0 / 100，全部在 600 秒比赛时限内。时长 P10/P25/P50/P75/P90 分别为 118.33/132.315/151.29/172.135/186.332 秒。固定 ranked 表单从约 P10/P30/P50/P70/P90 各取一套，5 套内目标物、混淆物和障碍物锚点分别都不重复；其余 193 套冻结为候选练习池，两个池严格不交叉。ranked 与 practice 选择在 HMAC 输入中使用不同 purpose 域，且分别携带冻结的选择策略版本；目录模块已经提供这两类 v2 选择 API，但当前 `/api/v1/evaluation-batches` 练习流程仍固定使用 v1 六套兼容目录，尚未启用 193 套池。

命令行报告只输出上述数量、分位数和聚合验收值；参考动作序列、布局编号、锚点和世界坐标留在服务端私有校验工具中，不进入静态页面、公开接口或学生示例。该基线证明候选布置存在完整安全解，不代表公开了一条推荐路线，也不改变系统没有自动寻路 API 的边界。

单局服务端重算分数记为 `s_i`，当前口径下 `0 ≤ s_i ≤ 100`。只有完整通过确定性重算且不是超时的记录可保留重算分数；重放报告为 `invalid` 或结束原因为 `timeout` 时，该局立即终结并计 0 分。主动关闭或批次过期会把所有剩余局原子终结为 `missing / 0`。固定五局分母不会因缺局缩小：

```text
meanScore  = (s1 + s2 + s3 + s4 + s5) / 5
minScore   = min(s1, s2, s3, s4, s5)
batchScore = 0.70 × meanScore + 0.30 × minScore
```

三个值均按 `/100` 展示。`valid` 只说明该局记录通过确定性复算，不等同于 8 个任务单元全部完成；`completed` 另行记录。校验 Worker 超时、繁忙、请求损坏等没有形成最终重放结论的基础设施错误不会消耗当前局，页面可重试。相同原始记录字节可幂等重试并取得同一归档结果；当前局已有最终记录后，内容不同的再次提交会被拒绝。

批次详情、租约、提交和关闭都要求当前登录账号为批次所有者；写接口还要求同源请求。详情类响应统一使用 `chenlong.batch-api-response/v1`，包含 `authoritative: false`、公开 `batch` 和公开 `currentSlot`：

| 方法与路径 | 请求 | 冻结行为 |
| --- | --- | --- |
| `POST /api/v1/evaluation-batches` | `{ "source": "..." }` | 创建固定 5 局批次并锁定源码摘要；之后每局记录的 `sourceCodeDigest` 必须一致。同一账号对完全相同源码重复或并发创建时，若已有未过期且未结束的同源批次，服务端原子复用同一 `batchId`，只计一次机会；已结束或已过期后再次创建才计为新机会。 |
| `GET /api/v1/evaluation-batches?phase=open` | 无 | 只发现当前登录账号最多 2 个未结束批次，按创建时间倒序返回批次 ID、期限、下一局、源码摘要和公开汇总；不返回源码、布局承诺、当前/未来布局、场次或运行定义。 |
| `GET /api/v1/evaluation-batches/:batchId` | 无 | 读取该账号拥有的公开状态与汇总；不返回源码、私有布局、物体坐标或已绑定场次细节。 |
| `POST /api/v1/evaluation-batches/:batchId/current-slot/lease` | `{ "teamId": "...", "slotIndex": n }` | 只允许 `n` 等于当前局。首次申请创建场次并返回 `lease`；重复申请恢复同一 `sessionId/runId/runDefinition`。租约包含当前局布局，不含未来局，也不含批次提交令牌。 |
| `POST /api/v1/evaluation-batches/:batchId/slots/:slotIndex/sessions/:sessionId/submissions` | 当前局 `RunRecord` JSON | 核对账号、当前局、场次、运行定义和锁定源码，隔离重算并归档；只有该原子步骤成功后才推进下一局。 |
| `POST /api/v1/evaluation-batches/:batchId/close` | `{}` | 最终关闭批次，把当前及后续所有未完成局写为 `missing / 0`，不可继续。 |

### 本地筛选五局后端契约

本地筛选使用固定竞赛标识 `2026-r2-gyi-local-screening.1`，接口前缀为 `/api/v1/competitions/2026-r2-gyi-local-screening.1/ranked-evaluation`。它与上面的练习批次分开存储；原 `/api/v1/evaluation-batches` 仍按 v1 六套兼容目录和 20 次练习政策运行，不进入筛选榜单。筛选接口如下：

| 方法与路径 | 请求 | 后端契约 |
| --- | --- | --- |
| `POST .../ranked-evaluation` | `{ "source": "...", "teamId": "..." }` | 每个 `(competitionId, ownerUserId)` 永久只有一次；首次返回 201，同源码、同队伍恢复返回 200，任一字段变化返回 409。源码 UTF-8 上限为 128 KiB，创建时冻结源码、队伍、评分政策和 v2 固定五套 holdout form。若进程在一次制台账落盘后、批次目录创建前中断，`GET .../me` 返回 503 `RANKED_ATTEMPT_RESERVATION_INCOMPLETE`，只有原源码和原队伍再次 POST 才能完成该预留。 |
| `GET .../ranked-evaluation/me` | 无 | 返回本人唯一一次筛选或 `evaluation: null`。本人投影始终使用固定 11 键：`purpose, competitionId, lockedTeamId, evaluationPolicy, createdAt, expiresAt, batch, currentSlot, anonymousParticipantId, lockedSource, result`；进行中 `result: null`，终态为本人匿名成绩。 |
| `GET .../ranked-evaluation/:batchId` | 无 | 仅所有者读取，使用同一 11 键投影。 |
| `POST .../:batchId/current-slot/lease` | `{ "slotIndex": n }` | 不接受客户端 `teamId`；场次始终使用批次冻结的队伍。响应额外含当前局 `lease`，不返回未来布局或提交 token。场次 `expiresAt` 钳制为不晚于父批次 `expiresAt`；练习批次租约也遵循同一容量规则。 |
| `POST .../:batchId/slots/:slotIndex/sessions/:sessionId/submissions` | 当前局 `RunRecord` JSON | 只接受该局绑定场次、冻结队伍和冻结源码。归档的 `receivedAt` 必须位于半开截止区间 `[boundAt, expiresAt)`；等于截止时刻即拒绝且不落归档。每个批次场次最多原子归档一份记录。 |
| `POST .../:batchId/close` | `{}` | 对账已归档证据后把未完成局固定为 `missing / 0`，返回同一所有者投影。 |
| `GET .../ranked-evaluation/ranking?offset=0&limit=100` | 无 | 登录用户可读匿名榜；只包含 `rank, anonymousParticipantId, score, quality, ranking`，不含账号、队伍、源码、批次、布局、场次或运行定义。 |
| `GET /api/v1/admin/competitions/2026-r2-gyi-local-screening.1/ranked-evaluation/ranking?offset=0&limit=100` | 无 | 仅管理员可读，在匿名成绩外关联账号显示字段、冻结队伍、创建时间和终态原因；仍不返回源码、布局、场次或运行定义。 |

筛选操作响应使用 `chenlong.ranked-evaluation-api/v1`，榜单使用 `chenlong.ranked-ranking/v1`，全部明确 `authoritative: false` 并带 `Cache-Control: no-store`。榜单只纳入 `purpose=ranked` 的终态批次；十个公开排序字段完全相同者并列，服务端私有稳定键只决定并列行的稳定显示次序，不改变名次。全局榜单刷新会先对账截止前已归档但尚未写入批次回执的记录，再逐回执核对 session/team/source、record/report SHA-256、归档时间和从原始报告重算的结果；证据缺失或改变时 fail-closed。大目录枚举、逐批次收口和证据审计在只读阶段完成，不持有全局排他锁；最后只用无 I/O 的短写阶段校验代际并发布快照。筛选提交使用截止优先的读准入，可越过正在等待发布的快照写阶段，旧候选因提交改变代际后只能返回 503 重试，不能延误已到达的提交。HTTP 分页在 3 秒受控快照内复用同一份全局审计结果，管理员一次可读取 101 页而不会触发默认限流或重复扫描全档案；冷缓存并发读取共享一次刷新。

磁盘上，练习批次继续使用 `chenlong.batch-store-payload/v1`；筛选独立实例使用严格的 `chenlong.batch-store-payload/v2`，并在独立 `attempts/` 目录保存 `reserved/bound` 一次制台账。创建在批次目录写入前先持久保留机会；同输入可完成中断的保留，`bound` 台账对应批次缺失时按归档损坏拒绝，不能重新考试。筛选 v2 回执额外绑定 `reportSha256` 和归档 `receivedAt`，重启可用唯一匹配的 SubmissionStore 证据补写回执。SubmissionStore 为新场次写私有 `scope.json`，把场次固定为 `single/practice/ranked` 及批次局号；通用单局提交路由拒绝 practice/ranked 场次。批次场次的持久 `expiresAt` 同时钳制到父批次截止，因此无人再次读取时，过期场次也会从活跃容量计数中自动释放。完成、关闭或过期后另写严格的 `retirement.json`，保留归档读取能力但立即释放活跃场次容量；标记缺失或损坏不会释放容量。服务端默认分别为 single、practice、ranked 保留 600、200、200 个活跃名额，总和仍受 `MAX_SESSIONS=1000` 的硬上限约束。证据审计 LRU 的容量覆盖 SubmissionStore 最多 10000 个保留场次形成的全部可能回执，避免全榜刷新周期性重读同一工作集。

练习模式中，每个账号最多同时有 2 个未结束批次，并且最多创建 20 个练习五局批次，也就是 20 次练习机会。这两个数字是当前明确的练习政策，不是页面提示：创建操作在服务端原子检查，超过任一上限即拒绝。关闭或过期只会释放“2 个未结束”的并发名额；已创建练习无论完成、主动关闭还是过期都占用 20 次机会中的一次且不返还，当前也没有面向参赛者的删除接口可以重置次数。筛选模式不复用这组配额，而是每个 `(competitionId, ownerUserId)` 只允许唯一一次。

文件存储的并发模型限定为单主机、单写 Node 进程。服务启动时会在数据根目录原子取得带进程和随机令牌的 writer lock；同一数据目录已有活动写进程时，第二个服务进程拒绝启动。进程异常退出留下的有效锁同样 fail-closed：运维必须先确认旧 PID 已停止，再显式移除锁文件，服务不会自动回收并承担两个进程同时写盘的竞态风险。在此边界内，存储层串行变更并由每批次操作锁覆盖“重算、归档、推进”；它不是数据库事务或跨主机分布式锁，不能据此把服务横向扩展为多个写实例。

批次状态文件会为已创建且未结束的五局状态推进预留空间，因此关闭、过期和批次汇总不会被后续批次状态增长挤占；这项预留不跨越到单局场次与 RunRecord 归档目录。若普通场次或记录归档已达到其独立容量上限，当前批次仍可能无法申请下一局或保存该局记录，但可以安全关闭或等待过期收口。页面会把这些容量错误明确提示给用户；正式比赛后端仍需用统一数据库配额与事务消除这一文件存储限制。

浏览器的批次按钮是一键自动串行工作流，不复用“单局运行后手动提交”的交互：源码锁定后自动运行当前局，等待服务端确认，再申请下一局。停止批次需要确认，剩余局按 `missing / 0` 计入。页面刷新恢复的边界如下：

- 当前标签页的 `sessionStorage` 保存批次 ID、锁定源码和参赛标识，是完整恢复的快路径；页面用它读取服务端公开状态并校验 `sourceDigest`，不持久化租约、私有布局或提交令牌。
- 刷新后不会自动执行学生程序；页面显示“继续当前五局评测”，由用户显式继续。若当前局已经租出但尚未形成服务端最终结果，再次租约会返回同一场次和运行定义，并从该局重新运行。
- 若 `sessionStorage` 不可用、被清空或用户打开新标签页，页面可调用账号级未结束批次发现接口。发现结果只够显示“恢复/关闭”提示；由于它不返回锁定源码或当前局租约，页面不会静默执行程序。用户必须显式选择，且恢复执行前仍须取得与 `sourceDigest` 匹配的锁定源码；无法取得源码时只能关闭或回到仍保存源码的标签页。
- 换账号不能看到原账号的批次；批次过期后也不能继续执行，剩余局会在发现、公开读取或关闭时按 `missing / 0` 原子最终化。
- 当前局必须下发到本地浏览器才能仿真，所以熟悉开发者工具的人可以检查当前 `runDefinition` 和物体位置。承诺与顺序下发保护的是未来局不被提前获知，不能把该设计描述为强反作弊或权威比赛执行环境。

五局流程没有 `route_to`、`go_to`、`pathfind` 等自动寻路接口，也不会从私有布局生成推荐路线。学生程序仍须结合 `mission()`、`task_state()`、`odometry()`、`road_state()`、`map_graph()`、摄像头结果和有界的 `follow_road()` / `take_exit()`，自行实现路线搜索、出口选择、重规划、绕障与抓放策略。

## 导航传感与局部道路控制

广阳岛的导航能力分成“只读传感”和“有界局部控制”两层。传感层只给参赛程序自己做决策所需的信息：`mission()` 给出当前冻结地图中不含坐标的道路级任务锚点，`task_state()` 给出真实任务进度，`odometry()` 给出相对程序起点的里程计，`road_state()` 给出当前道路局部状态、道路进度和当前节点的全部合法出口，`map_graph()` 给出没有坐标、物体或推荐路线的道路拓扑。它们每场合计最多查询 1,000 次，查询本身不推进仿真 tick。

控制层只有以下两个 Python 方法：

| 方法 | 参数 | 行为边界 |
| --- | --- | --- |
| `await robot.follow_road(max_cm=100, speed=40, obey_speed_limit=False)` | `max_cm` 为 10～500 厘米；`speed` 为 10～100 的速度百分比；`obey_speed_limit=True` 会逐 tick 按冻结道路和限速区钳制实际速度 | 仅沿调用时所在道路居中前进；达到请求距离，或在路口、道路端点、前方碰撞余量不足/道路安全边界处停车。不会转入另一条道路，也不会绕开障碍。 |
| `await robot.take_exit(road_id, speed=30, obey_speed_limit=False)` | `road_id` 必须是 1～128 个可打印字符，并应取自当前 `robot.road_state()["exits"]` 中的 `roadId`；`speed` 为 10～100；`obey_speed_limit=True` 会逐 tick 按冻结限速钳制 | 仅在当前道路节点执行该出口，沿相邻道路进入约 25 厘米后停车。叶端非单行道路可选择当前道路折返；系统不会改选其他出口；不在节点、出口无效、单行方向不允许时拒绝执行。 |

两个方法返回结构完全相同的字典，且不会附带世界坐标、碰撞体编号、内部控制命令或推荐路线：

| 字段 | 含义 |
| --- | --- |
| `accepted` | `true` 表示局部控制具备执行条件并已开始处理；`false` 表示调用位置或所选道路不满足条件，车辆不移动。 |
| `stoppedBy` | 本次停止或拒绝原因，取值见下表。 |
| `roadId` | `follow_road` 的当前道路，或 `take_exit` 请求/进入的道路；离路且无法执行时可为 `null`。 |
| `distanceCm` | 本次动作实际累计行驶距离，单位厘米，不是请求距离的回显。 |
| `elapsedTicks` | 本次动作消耗的 20ms 固定仿真 tick 数，单动作安全上限为 5,000 tick。 |

`stoppedBy` 的冻结取值如下：

| 取值 | 含义 | `accepted` |
| --- | --- | --- |
| `max_distance` | `follow_road` 已达到 `max_cm` | `true` |
| `junction` | 已在道路进入路口前停车 | `true` |
| `road_end` | 已到当前道路端点 | `true` |
| `front_clearance` | 前方动态障碍、固定边界或碰撞余量不足，提前安全停车 | `true` |
| `entered_road` | `take_exit` 已驶入指定相邻道路 | `true` |
| `off_road` | 调用 `follow_road` 时车辆不在有效道路上 | `false` |
| `wrong_way` | 当前行驶方向违反单行属性 | `false` |
| `not_at_junction` | 调用 `take_exit` 时车辆不在路口 | `false` |
| `invalid_exit` | 指定道路不在当前 `exits` 中，或不是可进入的相邻道路 | `false` |
| `collision` | 执行过程中仍触发碰撞兜底 | `true` |
| `safety_limit` | 到达单动作 tick 上限或无法保持在允许道路走廊内 | `true` |
| `time_limit` | 比赛时限或回放终止 tick 到达 | `true` |

局部控制每场最多 300 次，与只读传感的 1,000 次预算相互独立；参数格式通过校验后，即使因 `off_road`、`wrong_way`、`not_at_junction` 或 `invalid_exit` 返回 `accepted: false`，也会占用一次控制预算。`follow_road` 与 `take_exit` 不是自动寻路：前者不搜索目的地，后者不决定出口，两者都不提供自动避障。学生需要结合拓扑、里程计、局部道路状态和摄像头结果，自行实现路线搜索、出口选择、重规划及障碍处理。兼容冻结 v1 控制结果时，若 `follow_road` 返回 `junction` 而紧接着的 `road_state()["atJunction"]` 仍为 `False`，允许只执行一次 `robot.forward(2)` 前探并立即重读传感器；确认进入路口后才调用 `take_exit`，不得盲目循环前进。

## 广阳岛地图说明

当前页面不再重新手绘岛形和道路，而是把仓库内的《广阳岛仿真沙盘地图.png》主体区域直接铺成 `40 × 24` 仿真单位的矩形纹理，因此道路形状、景点文字和停车区均来自同一张原图。图中标注的沙盘尺寸约为 `5m × 3m`，配置采用 `1m = 8 仿真单位`。斜视和跟随视角会在纹理上叠加按原图像素标定的树林、建筑、湖面、花田、梯田、岩石、路缘和交通标志；俯视视角自动隐藏立体层，避免透视高度造成像素偏移。原图中的静态蓝色示意车会在运行时用相邻路面纹理修补，由动态仿真车辆替代。规则道路中心线仍是按原图像素人工描点得到的近似走廊，不是正式测绘数据。

正式地图冻结前需要组委会补充：

1. 原始矢量图或道路中心线坐标；
2. 5m × 3m 沙盘的准确比例、坐标原点和原图是否存在透视误差；
3. 车道宽度、停止线、路口、限速区和禁行区尺寸；
4. 任务点允许误差、车辆外形尺寸及碰撞阈值。

取得这些数据后，可直接替换已有的轮廓、中心线和区域配置；若正式数据包含车道级拓扑、停止动作、转向限制、交通标志或新的任务动作，则还需要扩展道路模型、`TaskEngine`、规则与评分器，不能承诺只换坐标。

```json
  ],
  "simulationEndTick": 125,
  "result": { "score": 53, "taskScore": 25, "ruleScore": 12, "simulationTick": 125 }
}
```

当前记录仍是客户端调试/演示记录，适合问题定位、教学讲解和确定性重放，但还不是可信比赛证据。v4 的 `seq` 在 inputs、samples、visionFrames、events 间全局递增；核心显式记录最终仿真 tick，并要求该 tick 存在终止遥测。`ReplayPlayer` 只以 `runDefinition + inputs` 驱动车辆、包裹、任务、规则和评分，samples/events/result 不会反向改写重算状态；`verify()` 会报告时间、状态相位、包裹、事件和结果差异。交互输入只表达“抓取/释放意图”，目标包裹、落点、堆叠层级和碰撞体由版本化核心重新推导。

自然完成和超时由任务状态与仿真 tick 推导；程序错误、人工停止、页面看门狗等外部终止则写入受限的 `run_end` 输入。重放会拒绝用伪造的 `run_end: completed/timeout` 覆盖核心判定，也会诊断终止之后追加的输入。

视觉证据验证 PNG 头、尺寸、字节数、SHA-256、全局顺序以及“查询只能引用此前画面”的因果关系；单帧和整场均有体积预算。当前回放不会重新运行浏览器内的 CV/YOLO 模型，因此有视觉查询时会诚实标记 `visionDetectionsRecomputed: false` 和 `visionStatus: "not_recomputed"`，而不是把已记录识别结果冒充重新识别。报告同时保留旧的 `recomputationComplete: false` 全范围口径，并用 `deterministicRecomputationComplete` 与 `verificationScope` 说明基础控制、导航查询、局部道路控制、物理、交互、任务、规则和成绩是否完整重算；其中 `navigationQueriesRecomputed` 与 `navigationControlsRecomputed` 分别标识两个导航域。视觉未重算是限制码，不再把确定性校验状态降为 `partial`。随机种子已经驱动仿真专用 PRNG，但当前车辆模型没有随机扰动。

回放最多处理 10,000 条输入和 50,000 个 tick，并对碰撞体、物理计算、任务/规则几何及视觉数据设置复杂度上限；损坏、恶意或超限记录返回诊断并停止推进，不能同步卡死页面。v3 继续按控制输入重建车辆轨迹，但不声称完整重算抓放或最终分数；v2 只提供 telemetry fallback 与 `rejudgeTask()` 支持。

所有本地重放与重判仍返回 `authoritative: false`。即使 `scoreRecomputed: true`，也只说明在这份客户端提供的版本化定义和输入下完成了独立计算，不证明任务定义、源码、输入或画面来自可信比赛环境。正式成绩必须由服务端使用签名赛题、完整离散输入、服务器时钟和重放结果确认。

本地后端、未来权威后端或 CI 都可以调用同一重放核心：

```bash
npm run verify:record -- path/to/RunRecord.json
```

`tools/verify-run-record.js` 接受文件或标准输入 `-`，并只输出向后兼容扩展后的 `chenlong.verification-report/v1` JSON。退出码 `0` 表示确定性校验范围完整重算、原始结果字段齐全且一致；视觉查询未在重放端重新识别时仍返回 0，但会明确给出 `visionStatus: "not_recomputed"` 和限制码。退出码 `2` 表示旧版记录、确定性重算不完整或结果对照不完整，`1` 表示损坏或不一致，`64` 表示命令/文件/JSON 输入错误；`--allow-partial` 可让 `partial` 返回 0，但不会改变报告状态。输入必须是严格 UTF-8，限制为 40 MiB；报告限制为 512 KiB，并会截断过多或过深的诊断字段，避免恶意记录放大输出。报告中的 `verified` 仅表示确定性范围内部一致，`authoritative` 仍固定为 `false`。

`server.js` 暴露同一能力：`GET /api/health` 返回版本和限制；`POST /api/v1/auth/register|login|logout` 与 `GET /api/v1/auth/me` 提供本地账号会话，注册分组严格限定为小学组、初中组、高中组三档，旧 `primary_low` / `primary_high` 及小学低、高年级文案统一规范化为 `primary`（小学组），旧初中和高中值分别规范化；`GET /api/v1/records` 只返回当前用户记录，`GET /api/v1/admin/records` 只允许管理员查看全部记录，并额外投影从可信 `navigation_query` / `navigation_control` 输入推导的管理员专属能力标记；`POST /api/v1/verify-run-record` 接收 RunRecord JSON；`POST /api/v1/sessions` 创建绑定当前用户的本地单局场次，带场次 Bearer token 的 `POST /api/v1/sessions/:id/submissions` 校验并归档记录。能力标记不读取源码文本，不会被注释或字符串触发，也会从个人列表、详情、回执和公开核验响应中剔除。五局工作流则使用 `/api/v1/evaluation-batches` 路由组，以登录账号、批次当前局和服务端保存的场次绑定授权提交，不向页面签发批次提交 token。首个注册用户成为本地管理员，密码使用 scrypt 哈希，登录 Cookie 为 HttpOnly/SameSite Strict，磁盘只保存登录及单局场次 token 的 SHA-256。单局场次和批次默认 8 小时有效，提交按原始字节 SHA-256 幂等；数据默认位于 `.runtime/`，进程重启后可以恢复。服务默认只监听 `127.0.0.1:6178`。

## 当前不能作为正式比赛系统的部分

- 浏览器仍可被开发者工具篡改，HUD 分数不是权威成绩。
- 虚拟视觉已经切换为车载摄像头像素识别并保存 PNG/SHA-256 证据，内置检测覆盖三类任务物体及视觉标记；共享像素核心与严格 640×480 PNG 解码已用于浏览器/Node 一致性建设。即使服务端能证明“该 PNG 会得到该识别结果”，它仍不能证明 PNG 一定来自真实赛场渲染，因此回执继续保持 `authoritative: false`。
- 基础车辆控制、导航查询、局部道路控制、抓放、包裹堆叠、任务、规则、人工介入和数值总分已经能从 v4 输入独立重算。普通单局的运行定义仍来自客户端；五局模式改由服务端冻结当前局运行定义并锁定同一源码，但运行和输入仍在可篡改的浏览器中产生，因此两类结果的 `authoritative` 都始终为 `false`。只有可信执行环境或服务端逐输入接收、计时并重放后，才可作为正式成绩。
- 当前 CLI 仍使用标准 `JSON.parse`，重复对象键会采用最后一个值；正式服务端验签入口必须在签名验证前使用拒绝重复键的流式 JSON 解析器。
- 当前 Node 服务只绑定本机；虽然已有 scrypt 本地账号、HttpOnly 登录会话、服务端冻结赛题、场次/运行号/用户绑定、20 次五局评测机会、原子文件归档、字节级幂等和数据目录 writer lock，但锁的安全边界只是单主机单写 Node 进程。系统仍没有正式身份认证、数据库事务、跨主机锁、签名密钥、服务器侧逐输入采集或成绩发布能力，不能直接暴露到公网充当比赛后端。
- v2 五局布局目录经过内部安全路线的 198/198 全量可解性验证，并从 198 套中冻结难度分层且锚点不重复的 5 套 ranked 表单；当前练习流程仍主动使用旧 v1 六套兼容目录，v2 的 193 套候选练习池尚未接入。顺序下发不会提前暴露未来局，但正在执行的当前局必须把 `runDefinition` 和物体位置交给本地浏览器，开发者工具可以检查或干预。它用于筛选对多布置不稳定的硬编码方案，不构成强反作弊证明。
- 地图底图来自给定 PNG，立体层高度和不可见侧面则根据单张俯视图估算；判分道路仍是像素描点近似，尚未经过官方矢量坐标校准。
- 当前纯核心任务判定覆盖 `checkpoints`、`reach`、基础 `delivery`，以及把目标物入库、混淆物道路外移除、顺序巡检、指定障碍零碰撞和返航组合起来的 `composite` 草案；规则仍只是初版子集，正式任务动作及判分口径仍待任务书补齐。
- 评分细则是配置草案，讨论稿权重与参数都必须以最终发布的正式任务规则替换。
