# Blockly 项目部署说明

本文件用于 Blockly 子项目维护、数据迁移和故障排查。正式比赛必须从统一平台根目录启动，统一交付、安全配置和恢复要求以 [`../../DELIVERY.md`](../../DELIVERY.md) 为准；不要把本子服务当作独立参赛入口。

## 运行要求、目录和数据

统一平台及本子服务最低要求 Node.js **22.13**。下列路径均相对于 `projects/blockly-page3/`：

    .blockly-data/primary-blockly-store.json
    .blockly-data/primary-blockly-records.sqlite

JSON 核心文件包含兼容数据、队伍关联、会话和三项任务的地图版本；SQLite 文件保存运行记录、正式提交和查询索引。两者还保存相同的随机数据库身份，必须作为一套恢复；缺失或身份不一致时服务会停止，不能用另一空库或同记录数数据库替换。服务运行时还可能存在 SQLite 的 `-wal` / `-shm` 文件，因此更新程序前应先停止全部平台服务，再复制整个 `.blockly-data` 目录，不要只复制其中一个文件，也不要与 Python 项目的数据目录混用。

普通交付 ZIP 会携带制作交付包时确认保留的冷态正式数据，但不包含管理工作区的 `record-backups/`。交付快照不是恢复备份；正式更新前仍须另做一份加密、可恢复的停服备份。

## 统一平台启动（正式方式）

在统一平台根目录执行：

    .\VERIFY-WINDOWS.cmd
    .\START-WINDOWS.cmd

参赛者只访问统一入口 `http://127.0.0.1:6190/` 或其正式 HTTPS 域名。反向代理只能转发到 `127.0.0.1:6190`，不得把 Blockly 的 `6180` 直接暴露到局域网或公网，否则会绕过统一身份、来源校验和成绩汇总。

## 子服务维护启动

只有在隔离的本机维护环境中才单独启动 Blockly。以下命令从统一平台根目录执行，数据路径由当前位置相对解析，不依赖开发机盘符：

    Set-Location .\projects\blockly-page3
    $env:HOST = '127.0.0.1'
    $env:PORT = '6180'
    $env:BLOCKLY_DATA_DIR = (Join-Path (Get-Location) '.blockly-data')
    node server.js

维护健康检查为 <http://127.0.0.1:6180/api/health>。单独启动时不要同时让统一启动器或另一进程写同一数据目录。

## 公网来源

正式公网只配置统一网关的 `CHENLONG_PLATFORM_PUBLIC_ORIGIN`，由统一启动器向子服务传递正确来源。临时隧道域名不得写入正式配置；域名变化后必须使用新 Origin 重启整套平台。`BLOCKLY_PUBLIC_ORIGIN` 仅用于隔离的旧版独立维护场景，不是统一交付的正式配置入口。

## 更新步骤

1. 停止旧服务并备份整个 `.blockly-data` 目录。
2. 确认 Node.js 版本不低于 22.13。
3. 运行 `npm test`。
4. 运行 `npm run test:browser`。
5. 保持原 `BLOCKLY_DATA_DIR`，从统一平台根目录启动新版本；正式公网同时保持统一网关的固定 HTTPS Origin 配置。
6. 首次升级等待旧 JSON 记录迁移完成，并确认 `/api/health` 的 `recordStorage` 为 `chenlong.blockly-record-database/v1`。旧 v8 核心文件第一次由新版本启动时会把现存记录库身份写回核心文件，之后每次启动都严格校验。
7. 检查本地和公网 /api/health。
8. 在专用 QA 数据上运行 `npm run test:live` 做真实写入验收；正式比赛期间不要运行。测试项数量会随回归补充而变化，最终以实际交付 ZIP 的完整输出为准。

服务启动时会自动把旧版 v1–v7 核心数据迁移为 v8，并为三项任务建立初始地图修订。旧运行记录迁入 SQLite 前会生成带内容摘要的 `pre-sqlite` 备份；事务导入、数量和逐条 ID 校验全部成功后才压缩核心 JSON，迁移不会删除原用户和成绩。

## 回滚

如果新版本无法启动：

1. 停止服务。
2. 保留故障时的数据文件副本。
3. 整体恢复更新前备份的 `.blockly-data` 目录和程序文件，不能混用不同时间点的 JSON、SQLite 或 WAL 文件。
4. 使用原环境变量重新启动。

不要在服务仍写入数据时直接覆盖数据文件。

## 离线和保密边界

Blockly、Three.js、图标和地图浏览器资源已经随项目本地提供，参赛页面不依赖 CDN。官网 SSO、成绩下载以及统一平台中的识物工坊首次模型加载仍有各自网络要求，详见根目录交付说明。

数据目录含密码派生信息、邀请码、积木结构、生成代码和正式成绩，只能由组织方及授权运维人员持有。不要把项目源码、数据快照、历史备份或平台/官网密钥发给参赛者；任何正式密钥都不得写入本说明或启动脚本。
