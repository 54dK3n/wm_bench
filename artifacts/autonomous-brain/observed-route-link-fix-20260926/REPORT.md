# 公开观测行程接入决策状态

navigation v5、runtime v11、actions v20、LLM v13已实现。车只把自己实际走完的出发出口与到达路口记录为有向行程，并给大模型至多三个下一出口建议。此报告验证接入与回放，不宣称正式任务成功。

## 变化与边界

旧navigation v4作为私有基类保留；其道路采样、节点定位、出口访问/完成/阻挡和未探索数量算法不变。新记录需要连续公开观测、真实动作结果、唯一当前出口、不同的实际观测到达节点和里程证据。当前观测到达前的动作若被拒绝、碰撞、净空不足、离路或错误，即取消该窗口；不以旧completed标志证明走通。抓放、新出发和显式阻挡也取消旧窗口。

窗口跨动作及决策轮保留，包含全部静止帧和转向；首个短步仍在原路口时继续等待。Runtime在同tick快照建立后，向收集器提供实际执行器结果和最终观测编号。成功及拒绝事件写入对应`observations.jsonl`的`road_traversal_events`；完成记录含完整动作引用和公开里程路径。`motions.jsonl`保持每个动作单条记录。

提示只使用明确走过的方向。当前点及相邻行程连接要求公开位置完全相同、同一记忆节点、完整出口上下文在原5°范围内双向唯一；第一角必须是当前观测的原始相对出口。历史目标出口沿用15cm局部范围并显式保留位置间隔，到达后仍须重新观察。没有证据则留空，不补反向道路或无观测连接。

Runtime只把提示的紧凑字段交给模型；模型仍返回原六种动作中的一个。提示不直接控制车，不修改WorldModel或完成条件。CONFIRMED前置、原抓放判定、未探索出口必须为零、200轮和1200仿真秒均保持。空提示不代表探索完成。

- [完整回归](integrated-tests-v2.txt)：707项通过。新增真实Runtime/Actions配合传感器替身的测试覆盖阻挡到达、跨轮与静止帧、短起步、原生completed字段、漏动作、旧标志不能补造行程及提示不修改未知数量。
