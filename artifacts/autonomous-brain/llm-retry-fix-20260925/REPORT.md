# 明确记录的有限连接重试

第二、三、四局分别出现超时、连接提前关闭和 URL 连接错误。第四局后，同配置的只读模型列表请求仍返回 HTTP 200。旧局均保持 FAIL；流式输出和更长等待不能保证连接始终可用。

客户端 v7 增加显式的连接重试上限。客户端默认仍为 0，正式大脑在 `run.py` 中设为 2：对一次 JSON 请求，初次失败后最多再尝试两次，分别等待 1 秒、2 秒。只处理列明的瞬态传输错误和 HTTP 408、429、500、502、503、504；400、401、403 等永久错误立即停止。

每次实际请求都保留完整输入、原始响应或连接错误、耗时、调用编号、重试上限、索引及等待时间。重发使用相同请求内容；收到完整合法动作前不执行运动。模型、温度、非思考模式和每局上限不变。

完整但非法的模型输出仍只有一次修复机会。传输重试不增加 JSON 修复次数；耗尽重试仍失败就结束该局。模型累计调用耗时为各次实际请求耗时之和，重试等待另外记录，可从日志复算。

离线回放从原记录恢复策略，不联网、不等待；旧版缺少重试字段时按 0 处理，不补写新字段。检查结果与源码 SHA256 见 `validation.json`、`SHA256SUMS`，真实第四局的旧失败重放见 `v6-error-replay/replay-checks.json`。这些检查不代表任务已完成。
