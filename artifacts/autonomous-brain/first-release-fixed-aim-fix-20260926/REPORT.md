# 首次放置固定观测瞄准点：Actions v18

本候选让首次放置也固定初始完整绿色框的中心地面点，避免在接近过程中持续追随变化或裁切后的框中心。生产修改只有 `autonomous_brain/actions.py`，版本 v17→v18；不改确认、抓取、送达门槛或任何历史运行结论。

首次放置必须先得到完整、尺寸合法且面积唯一最大的当前绿色分量，用现有公开相机标定投影其中心，再按当前里程计固定在初始坐标系。若中心落入当前红球、蓝球或障碍框原有半宽/半高扩展占用范围，保守失败并继续持物，不临时改选其他点。若看见已送达红球，则完整保留 v17 的左右四分之一候选、占用排除、距离评分与平分时选左规则。

后续仍要求每步有新鲜绿色检测；控制距离和方位来自固定点与实际里程计。原 `19cm / 3°`、最多八次平移、每次不超过7cm、每段最多三次对准转向、实测轨迹归路和放后唯一像素见证全部不变。绿色框后来裁切不会重新定义目标，绿色检测消失则停止。固定点只是一项观测支持的操纵目标，不声称是物理区域中心，也不能替代送达证据。

Run17 的只读传感复算支持这项候选，但没有证明改变轨迹后一定成功：

绿色框首次触底是 **obs214**。源代码按当前检测中最小距离选择控制分量，obs216出现多个绿色分量，因此表格按实际控制选择而非某个固定WM ID计算。以上地面坐标已用里程计消除车辆运动影响，证明变化的不仅是图像像素，而是逐帧追随的控制目标。

在实际 obs215 位姿，初始固定点为17.7903cm / −0.7812°，已满足原释放距离/方位；动态框中心仍为20.7588cm / 0°，所以旧控制继续前进。在实际 obs224 位姿，动态目标18.7041cm / −1.4770°允许释放，而初始固定点已为9.8716cm / −29.2333°。这些只是同一实际位姿下的参考点比较，**不是新策略的仿真轨迹或成功预测**。
