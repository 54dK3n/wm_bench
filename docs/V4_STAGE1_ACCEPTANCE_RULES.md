# v4 阶段 1 恢复验收口径

本轮按用户恢复指令重做三个布局各两次。旧 `artifacts/inloop/v4/stage-1/acceptance-01/` 的「record 确定性通过」与「经桥 observe 通过」两项**作废**，不得作为恢复后门禁的通过证据。旧文件保留原字节。白名单也在本轮重新测试。

## 来源和内容一致性

仿真实际检测来源必须保留为 `virtual-cv`，不得改标为 `yolo`。绿色地面检测器原生来源为 `storage-ground-pixels`，与旧立式存放点标牌区分。

内部视觉模块的旧类别 `target`、`distractor` 来自固定红色、蓝色像素分类，分别转换为公开外观类别 `red-ball`、`blue-ball`。`obstacle` 保持原类别。原生像素框位于 640×640 letterbox；公开框统一为 640×480 相机原图，去除 80px 上边距并裁剪至图像范围，置信度不舍入、来源不改写、顺序不重排。

本轮相等比较指上述**明确坐标与外观类别转换后**的逐条相等，不把不同坐标系直接相等当作目标。每次保留以下独立证据：

- `rawDetections`：原始 `CarVision.getDetections()`，包括桥不使用的旧标牌类别。
- `storageDetections`：独立绿色地面像素检测器的完整原始输出。
- `robotDetections`：平台内部机器人检测适配的四类完整输出。
- `bridgeObservation`：外部 HTTP 客户端实际收到的输出。

评测器不导入平台适配实现。它从前两项独立计算预期结果，同时比较内部适配与桥输出的数量、类别、像素框、置信度和来源。旧立式 `storage-zone`/`cleanup-zone` 标牌不是绿色地面，每条排除原因写入 `excluded_with_reason`；框完全在原图外等排除也显式记录，不能静默丢失。

验收脚本所有 observe 均使用不筛类别、最低置信度 0。全套六局按四类统计检测条数；任一类总数为 0 判失败。

## 应见统计

只在评测进程使用真值。相机原点到物体中心的地面平面距离在闭区间 30–85cm、水平相对方位绝对值不大于 30° 时，按「帧 × 物体」计一次应见。距离从相机开始计算，不从车体中心计算。无额外遮挡、像素大小、置信度等排除条件。

每次应见检查该帧桥是否输出对应类别；缺少对应类别计漏检并判失败。不增加框中心命中门槛，不把类别出现解释为实例召回。同帧有多个同类物体但仅一个检测时，明确记录类别证据的局限。若某类没有应见样本，报告未验证，不另增数值门槛。

## 确定性和 C-ENV-001

同一布局两次完整 record 逐字段比较，不删字段、不放宽浮点误差。同序 observe 的 RGBA8 原始像素 SHA256、frameId、tick 和 checkpoint 动画字段逐项比较。PNG 压缩文件摘要另存，不能代替像素摘要。

评测钩子在 `renderer.render(scene, virtualCamera)` 入口抓取实际相机矩阵、真值和动画字段，在原生视觉证据写入处绑定该帧 RGBA 字节。动画预期值按 `time = tick * stepMs / 1000` 从公式复算。每局包含同 tick 下暂停后再观测，以及 tick 推进后的观测。专项单测还禁止采帧时读取墙钟，验证渲染前会恢复正确动画相位。

所有评测钩子及导出只属于页面控制端；外部脚本只持机器人桥客户端凭证，通过里程计和相对出口角度完成固定预算道路巡查。真值、布局选择及检查结果从不用于选择动作。

## 复算与保存

正式新入口为 `tools/v4_stage1_content_acceptance.js`；旧入口保留历史复现用途。每轮必须写入新目录。报告、manifest 中的文件引用使用仓库相对路径。

离线复算：

```sh
node tools/v4_stage1_recompute.js \
  --input artifacts/inloop/v4/stage-1/restore-20260925/acceptance-02 \
  --out /tmp/v4-stage1-recomputed.json
```

复算程序退出 0 表示忠实复现已保存结论，不代表阶段 1 通过；实际验收看输出中的 `allPass`。未通过即停在阶段 1，不能进入阶段 2。
